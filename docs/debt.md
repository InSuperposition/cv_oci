# Accepted-compromise ledger

Known compromises accepted during planning, each with the trigger that should
prompt a revisit. Distinct from `TODOS.md` (new work). Reviewed at the start of
each slice.

| Compromise | Why accepted | Upgrade when | Target |
|---|---|---|---|
| Option A: the runtime image carries an in-process compiler (esbuild / oxc / lightningcss via `remix/node-tsx` + the asset server) | `remix@3` has no build step; its supported deploy model runs the asset server in production. CNB does not change this. | request-time bundling proves a determinism or security problem | Option C (snapshot assets to static) |
| Runtime image is `heroku/heroku:24` — a full Ubuntu 24.04 base (shell, `apt`, `npm`, Node) | adopting a stock CNB builder means adopting its run image; `heroku` has no distroless variant, and a probe of `heroku/builder:24` + `-run-image=paketobuildpacks/run-noble-tiny` failed at export (`MANIFEST_INVALID`, tiny image missing `io.buildpacks.base.distro.*` labels). Weaker than the retired crane/apko distroless runtime. | a compatible distroless multi-arch run image exists, or a second cluster / real deploy target raises the stakes | custom run image with the required base-distro labels, or switch builders |
| zot has no auth (anonymous push + pull) | the zot seed is unauthenticated by design | Slice 5 | htpasswd (`manifests/zot/`), the CI credential wired through `dockerconfig` + a Flux `imagePullSecret` |
| zot TLS is a self-signed cert-manager CA (not a public/real CA) | solo cluster; the CA never leaves it; `--insecure` clients tolerate it | a second node / real deploy target / an external puller | a real ACME/DNS issuer, or OpenBao PKI (`cv_openbao`) |
| Pipeline steps (lifecycle `create`, trivy `scan`) use `--insecure` against zot, not CA-trust | T3 deferred (eng review 2026-09-02): the `zot-tls` Secret is in `cv-pipeline`, the pipeline runs in throwaway `cv-e2e-*` namespaces; per-namespace CA distribution is machinery for a same-node MITM threat that does not exist on a solo single-node cluster. Only the Chains controller (stable ns) trusts the CA. | the pipeline runs in a stable namespace (Slice 5), or trust-manager / a CA-bundle mechanism lands | mount `ca.crt` (ConfigMap or per-ns `Certificate`), drop `--insecure` + `CNB_INSECURE_REGISTRIES` |

| No build cache (`SKIP_RESTORE=true`) | 1-dep app; a cache is another determinism variable and a zot round-trip per build | build time bites as `cv_frontend` deps grow | zot `CACHE_IMAGE` (TODOS.md: npm cache) |

Correct contents (names Node + the npm tree), but the provenance is "what the scanner saw in the image", not "what the buildpack installed". | a builder that emits real per-buildpack SBOMs (Paketo, once an arm64 build exists), or a dedicated syft/cyclonedx-npm step keyed to `package-lock.json` | build-time SBOM from the buildpack or lockfile |

## Resolved

| Was | Finding | Fix |
|---|---|---|
| "CNB builds are not byte-reproducible; the lifecycle does not honour `SOURCE_DATE_EPOCH`" | Not the lifecycle. Two independent builds of one fixture SHA already agreed on the SBOM layer and 10 of 12 other layer diffIDs, gzip-compressed digests included (`created` is pinned to `1980-01-01T00:00:01Z`). The **only** drift was the app layer, caused by our own `fetch` step leaving `.git/` (— `.git/index` stat cache, `.git/logs/HEAD` reflog timestamps —) in the source tree for the buildpack to copy in. | `pipeline/pipeline.yaml` `fetch` step `rm -rf .git` after the SHA is captured. Builds are now byte-for-byte reproducible (identical outer image digest). Guarded by `tests/build-is-reproducible` (Slice 2; Chainsaw as of Slice 5a). |
| CNB `buildpacks` task `prepare` step runs as root (uid 0) to `chown` the workspaces | `fetch` (`alpine/git`) wrote the source tree root-owned and `fsGroup` only sets the group on *new* files, so `prepare` chowned `/layers`, `/tekton/home` and the workspace to the builder uid. | Slice 1.7: `fetch` and every `buildpacks` step run uid 1000 with the full restricted `securityContext` (via `stepTemplate`), the inline `smoke`/`deploy`/`smoke-teardown` steps too; `prepare`'s `chown` is deleted; `fsGroup: 1000` on the podTemplate makes the PVC + emptyDirs group-writable; `cv-pipeline` enforces PSA `restricted`; `bootstrap.sh` sets `set-security-context=true` so Tekton's injected containers comply. No root anywhere in the pipeline. Verified: `e2e.sh` + `negative.sh` + `repro.sh` green under `restricted` (2026-09-01); the pipeline SAs cannot create pods (RBAC) and the namespace rejects non-compliant pods (PSA). |
